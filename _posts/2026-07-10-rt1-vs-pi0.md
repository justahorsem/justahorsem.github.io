# RT-1与π0对比：相同点与差异

RT-1 和 π0 都是在解决同一个根本问题：

```text
p(动作 | 图像, 语言, 机器人状态)
```

也就是让机器人根据当前视觉观察、语言指令和自身状态，生成可执行动作。

但它们代表了两代不同的 VLA 思路：

```text
RT-1：把机器人控制改写成离散动作 token 的自回归预测
π0：把机器人控制改写成条件连续动作分布的流匹配生成
```

一句话概括：

```text
RT-1 更像“机器人版 Transformer policy”
π0 更像“VLM 加上连续动作生成器”
```

## 1. 共同点：它们为什么都算 VLA

RT-1 和 π0 的差异很大，但底层目标是一致的。它们都试图把视觉、语言和动作放进同一个机器人策略系统中。

### 1.1 都以语言作为任务条件

二者都不是只看图像做反应，而是都接收语言指令。

例如：

```text
pick up the red cup
open the drawer
place the apple on the plate
```

语言的作用是指定任务目标，让同一个策略模型可以根据不同指令执行不同行为。

区别在于：

- RT-1 通常使用外部语言编码器把指令变成 embedding。
- π0 使用 PaliGemma 的原生语言 token 和 VLM 主干。

但从功能上看，它们都在做：

```text
language-conditioned robot control
```

### 1.2 都把视觉作为主要观察输入

二者都依赖相机图像理解环境。

RT-1 中，图像经过 EfficientNet、FiLM conditioning 和 TokenLearner，变成视觉 token。

π0 中，图像经过 PaliGemma / SigLIP 视觉编码器，变成和语言 token 可交互的视觉 token。

所以它们的共同结构都可以抽象成：

```text
image
  -> visual encoder
  -> visual tokens
  -> transformer / policy model
```

### 1.3 都把机器人控制转成序列建模问题

RT-1 和 π0 都不是传统控制理论里的手写控制器，也不是单步分类器。它们都把机器人动作看作一段序列。

RT-1：

```text
历史图像 token + 历史动作 token -> 下一个动作 token
```

π0：

```text
当前观察 + 带噪动作块 -> 未来动作块的向量场
```

虽然生成方式不同，但共同点是：

```text
动作不是孤立的一步，而是具有时间结构的序列。
```

### 1.4 都使用 Transformer 作为核心建模工具

RT-1 使用 decoder-only Transformer，把图像 token 和动作 token 拼成长序列，然后自回归预测动作 token。

π0 使用基于 Gemma 的多 expert Transformer。PaliGemma expert 处理图像和语言，action expert 处理机器人状态、动作和 flow matching 时间。

所以二者都依赖 Transformer 的序列建模能力，只是 token 类型和训练目标不同。

### 1.5 都依赖大规模机器人数据

二者都不是靠少量演示就能获得通用能力。

RT-1 的关键贡献之一就是证明：大规模真实机器人数据可以训练一个跨任务策略。

π0 则进一步扩大到多机器人、多任务、多数据源，并借助 VLM 预训练知识提升泛化。

共同点是：

```text
scale matters
```

数据规模越大，模型越可能从单任务拟合走向通用策略。

### 1.6 都是行为克隆 / 监督学习范式的延伸

从训练信号看，二者都主要从专家轨迹中学习：

```text
观察 -> 专家动作
```

RT-1 用真实动作 token 做 teacher forcing，训练模型预测离散动作 token。

π0 用真实动作块构造 flow matching 目标，训练模型预测从噪声到动作的向量场。

训练目标不同，但监督信号都来自机器人演示数据。

## 2. 核心差异总表

| 维度 | RT-1 | π0 |
|---|---|---|
| 代表思路 | 大规模 Robotics Transformer | VLM backbone + action expert |
| 基本建模 | 自回归序列预测 | 条件流匹配生成 |
| 视觉编码 | EfficientNet + FiLM + TokenLearner | PaliGemma / SigLIP 视觉编码器 |
| 语言处理 | 外部 Universal Sentence Encoder embedding | PaliGemma 原生语言 token |
| 动作表示 | 离散 action token | 连续动作块 |
| 动作生成 | 逐 token 自回归 | 从噪声积分生成 |
| 训练 loss | 交叉熵分类 loss | flow matching regression loss |
| 输出粒度 | 动作 token / 单步控制为主 | 未来动作块 |
| 语义泛化 | 主要来自机器人数据和语言 embedding | 来自 VLM 预训练 + 机器人数据 |
| 控制精度 | 受动作离散化影响 | 更适合连续高频控制 |
| 模型复杂度 | 相对简单 | 更复杂、更重 |

## 3. 第一性原理视角：它们对动作分布的假设不同

机器人策略要学的是：

```text
p(A | o)
```

其中：

```text
o = 图像 + 语言 + 状态
A = 动作序列
```

RT-1 的假设是：

```text
连续动作可以离散化成 token
动作生成可以像语言模型一样自回归预测
```

因此它把动作空间切成有限个桶：

```text
continuous action -> discrete token id
```

训练时就是分类问题：

```text
预测正确的 action token
```

π0 的假设是：

```text
动作本质上是连续分布
应该直接建模连续动作块，而不是强行离散化
```

因此它使用 flow matching：

```text
noise -> action
```

训练时学习一个向量场：

```text
v_theta(x_t, o, t)
```

表示在观察条件 `o` 下，带噪动作 `x_t` 应该往哪个方向流动，才能变成真实动作。

## 4. 架构差异：从“policy transformer”到“VLM + action expert”

### 4.1 RT-1 的结构

RT-1 的信息流大致是：

```text
image
  -> EfficientNet + FiLM
  -> TokenLearner
  -> visual tokens

language instruction
  -> Universal Sentence Encoder
  -> language embedding
  -> FiLM conditioning

action
  -> discretization
  -> action tokens

visual tokens + action tokens
  -> Transformer
  -> next action token logits
```

它的核心是：

```text
把机器人控制转成 token 序列预测
```

### 4.2 π0 的结构

π0 的信息流大致是：

```text
image + language
  -> PaliGemma / VLM expert
  -> semantic prefix tokens

state + noisy action + time
  -> action expert
  -> action suffix tokens

prefix + suffix
  -> multi-expert Transformer
  -> velocity field
  -> continuous action chunk
```

它的核心是：

```text
让 VLM 负责理解，让 action expert 负责连续动作生成
```

## 5. 动作表示差异：离散 token vs 连续动作块

这是 RT-1 和 π0 最关键的分叉。

RT-1 把每个动作维度离散化：

```text
a = 0.37
  -> bin index = 128
  -> action token
```

好处是训练简单，可以直接用交叉熵。

问题是：

- 离散化会损失精度。
- 长动作序列需要自回归生成。
- 对高频、灵巧、连续控制不够自然。

π0 不把动作离散成 token，而是直接处理连续动作块：

```text
actions: [H, action_dim]
```

例如 openpi 默认：

```text
H = 50
action_dim = 32
```

也就是一次生成未来 50 步动作。

好处是：

- 更适合连续控制。
- 更适合高频动作。
- 能表达多模态轨迹分布。
- 推理时一次得到一段动作，而不是逐 token 解码。

## 6. 语言能力差异：语言 embedding vs VLM 主干

RT-1 使用语言，但语言在 RT-1 里更像一个条件变量。

它通常先用外部语言编码器得到：

```text
natural_language_embedding
```

然后这个 embedding 用来调制视觉特征。

这意味着 RT-1 能区分不同任务，但它本身并没有一个强大的语言模型主干来做复杂语义推理。

π0 则直接继承 PaliGemma：

```text
图像 token + 语言 token -> VLM semantic representation
```

因此 π0 更接近真正的 VLA：

```text
VLM 的开放世界理解能力 + 机器人动作生成能力
```

这也是为什么可以说：

```text
RT-1 是带语言条件的机器人 Transformer
π0 是被改造成机器人策略的 VLM
```

## 7. 训练方式差异

### 7.1 RT-1：teacher forcing + 交叉熵

训练时，RT-1 把真实动作离散化成 token，然后让 Transformer 预测这些 token。

```text
真实动作
  -> action tokenizer
  -> action token
  -> Transformer logits
  -> cross entropy loss
```

本质是分类：

```text
哪个动作 token 是正确答案？
```

### 7.2 π0：加噪动作 + flow matching

π0 的训练更像 diffusion / flow policy。

给定真实动作 `A` 和噪声 `noise`，构造：

```text
x_t = t * noise + (1 - t) * A
```

模型输入：

```text
观察 o + 带噪动作 x_t + 时间 t
```

模型预测：

```text
v_t = noise - A
```

loss 是向量场回归：

```text
||v_theta - v_target||^2
```

本质是学习：

```text
如何把噪声动作流回真实动作
```

## 8. 推理方式差异

RT-1 推理更像语言模型解码：

```text
已有上下文
  -> 预测下一个 action token
  -> 写回状态
  -> 再预测下一个 token
  -> detokenize 成动作
```

π0 推理更像从噪声中生成轨迹：

```text
随机噪声动作块
  -> action expert 预测向量场
  -> 积分一步
  -> 再预测向量场
  -> 最终得到连续动作块
```

所以：

```text
RT-1: autoregressive decoding
π0: flow-based generation
```

## 9. 各自优缺点

### 9.1 RT-1 的优点

- 架构相对直接。
- 训练目标简单，交叉熵稳定。
- 证明了大规模真实机器人数据可以训练通用 policy。
- 对早期真实机器人多任务控制非常重要。

### 9.2 RT-1 的局限

- 动作离散化会损失连续控制精度。
- 语言理解能力主要依赖外部 embedding，不是真正的大 VLM 主干。
- 自回归动作 token 生成对长序列和高频控制不够自然。
- 泛化更多依赖机器人数据覆盖范围。

### 9.3 π0 的优点

- 直接继承 VLM 的视觉语言理解能力。
- 连续动作块更适合高频、灵巧控制。
- flow matching 能建模复杂、多模态动作分布。
- action expert 把语义理解和动作生成分工清楚。
- 更适合开放语言指令和复杂长程任务。

### 9.4 π0 的局限

- 模型更大，训练更复杂。
- 推理需要多步积分，部署成本更高。
- 对数据配方、归一化、动作空间适配更敏感。
- 真实机器人落地仍然依赖平台、控制频率和数据质量。

## 10. 如何理解二者的技术演进

可以把 RT-1 到 π0 的变化理解成三步演进。

第一步：RT-1 证明机器人控制可以序列化。

```text
image + language + action history -> Transformer -> action token
```

第二步：VLM 时代证明互联网规模视觉语言知识可以迁移到机器人。

```text
VLM understands objects, relations, instructions
```

第三步：π0 把 VLM 的理解能力和连续动作生成结合起来。

```text
VLM understanding + flow action expert -> continuous robot control
```

所以 π0 不是简单的“大号 RT-1”。它的关键变化是：

```text
动作建模范式从离散 token 分类，变成连续分布生成。
```

## 11. 最终总结

RT-1 和 π0 的相同点：

- 都是视觉-语言-动作模型。
- 都用 Transformer 建模多模态序列。
- 都以语言指令作为任务条件。
- 都依赖大规模机器人数据。
- 都把机器人控制从传统手写控制转向数据驱动策略学习。

RT-1 和 π0 的核心差异：

- RT-1 把动作离散化成 token。
- π0 直接生成连续动作块。
- RT-1 用自回归分类。
- π0 用 flow matching。
- RT-1 的语言更像条件 embedding。
- π0 的语言来自真正的 VLM 主干。

一句话：

```text
RT-1 是把机器人控制语言模型化；π0 是把视觉语言模型机器人化。
```
